# Requirements: Open data

## Introduction
Janus returns what it learns to research (product.md: "open dataset of aggregated counts"). This feature publishes
(B) an **open outcome dataset**: the doctor-confirmed outcomes layer and the donations, released only through the
existing Collective Memory rule (k = 20, noise, sibling rule), as a public aggregate page and downloadable CSV / JSON
with a data dictionary and CC BY 4.0, versioned with a snapshot date; and (C) an **open cascade data package** and a
**documented read-only API**: the PIPC-based rule base with Janus's mappings, name rules, ATC exclusions and dose-form
groups as versioned files with a licence per file, an OpenAPI document of the public GET routes, and a "Contributing
corrections" page listing the upstream data errors Janus found. Owner request 2026-11-09.

## Glossary
- **Released cell:** a (layer, one or two ingredient keys, event key, direction, region) count that passed the
  release rule. **Hidden cell:** any other; it is never listed.
- **Release rule:** `memory/shared.py` `release_cells`: k ≥ 20 on the true count, sibling rule, discrete Laplace
  noise deterministic per cell version (collective-memory Req 5, privacy design §6).
- **Public route:** a GET route that takes no body and returns no personal data.

## Requirements

### Requirement 1: Released cells only
1. THE dataset SHALL contain only cells released by `release_cells`, for the layers `contributions` and `outcomes`
   (assessment `confirmed`), for ingredient sets of one and two keys.
2. THE dataset SHALL NOT list a hidden cell, a true count, an age band, a sex, a week, a country, free text or any
   identifier.
3. WHEN the same data are stored, THE dataset SHALL give the same values (no noise redraw per request).
4. *(Safety review O1.)* A layer SHALL be published only WHEN every stored row of it was given under a consent version
   whose text names publication in the open dataset; otherwise THE whole layer SHALL be withheld and named.
5. WHEN there is no database or no noise key, THE API SHALL answer 503 `open_data_unavailable` and never serve
   counts without the rule.

### Requirement 2: Files, version, licence
1. THE API SHALL serve `GET /open/outcomes` (JSON) and `GET /open/outcomes.csv` (CSV) with the same cells.
2. THE JSON SHALL carry `version` (rule version + hash of the released cells), `snapshot_date`, the licence CC BY
   4.0 with its URL and attribution, the release rule, the data dictionary URL and notice codes; the CSV SHALL carry
   the version in each row and in a response header.
3. THE data dictionary SHALL be documented in English in `docs/open-data.md`.

### Requirement 3: The public page
1. THE web app SHALL show an Open data page (`/open-data`, linked from Research and the footer) with the released
   cells per layer as tiles and tables, the release rule, the downloads, version, snapshot date and licence.
2. WHEN no cell is released, THE page SHALL say "no released cells yet" and SHALL show no number for the dataset
   (no example number, no large zero).
3. THE page SHALL state that counts are reports, not people; that outcomes are not verified; that there is no
   denominator.
4. Demo mode SHALL answer from a file recorded from the real local API, with no request; downloads then come from
   that file.

### Requirement 4: The cascade data package
1. THE repository SHALL contain `data/open/cascade-package/` with the PIPC table, `pipc_rules.csv`,
   `cascade_classes.csv`, `atc_code_exclusions.csv`, `ingredient_synonyms.csv`, `anion_acid_forms.csv`,
   `dose_form_groups.csv`, a Frictionless `datapackage.json` and a README.
2. EACH file SHALL name its licence(s) and sources; the PIPC table SHALL keep CC BY 4.0 and its citation.
3. THE package SHALL contain no TİTCK string: no synonym row whose evidence cites TİTCK or the TİTCK-based coverage
   report, and no name that occurs in the TİTCK list (checked by hash; the names themselves are never committed).
4. THE package SHALL be generated by a builder; CI SHALL fail when the committed package differs from its output.
5. THE package SHALL be versioned (semantic version, creation date, a hash and row count per file).

### Requirement 5: The public API document
1. THE repository SHALL contain `docs/openapi-public.json`, generated from the API's schema, listing only public
   routes, with examples (empty dataset, a released cell, error codes); CI SHALL fail when it drifts.
2. `docs/open-api.md` SHALL describe each public route, its errors and the rules (codes not sentences, no-store,
   reports not people).

### Requirement 6: Contributing corrections
1. `docs/contributing-corrections.md` SHALL list the upstream errors Janus found (Wikidata ATC statements, TİTCK
   published codes) with the evidence and how to report each upstream.
2. Janus SHALL NOT submit anything upstream itself.

### Requirement 7: Quality
1. Properties: CSV ↔ cells; version changes iff the released content changes; the package has no TİTCK row; any
   TİTCK spelling is recognised.
2. Database tests: empty store → no cell; a group under 20 is never listed; a group of 20 is released with the same
   value as `/memory/shared`; the sibling rule hides a revealing cell.
3. The `OpenData` namespace in five languages; Playwright: axe, 375 / 1280, both themes, five languages, empty state,
   demo without requests.
